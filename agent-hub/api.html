一、设计原则

网关是 AgentHub 唯一的对外 HTTP 门面，承担 Agent 服务接入、能力调用与调用审计三类职责。 本次设计在现有骨架（仅 GET /healthz）基础上，补齐完整的接口契约， 并同时修正骨架中已发现的若干实现断点。核心原则如下：

  • 契约优先：先固化路径、请求/响应结构、错误码，再落地实现，避免前后端各自猜测。
  • 错误可编程：错误响应带稳定的机器可读 code，前端按 code 分支而非解析文案。
  • 租户隔离内建：所有读写均以 Principal.tenant_id 为边界，跨租户一律返回 404。
  • 审计不掉链：每次调用无论成功失败都落一条审计记录，以 request_id 为关联主键。
  • 不泄露内部：内部错误只回通用文案 + request_id，细节仅进日志。

二、通用约定

Base URLhttp(s)://<host>:<port>/v1（探针接口不带版本前缀）
Content-Typeapplication/json; charset=utf-8；流式响应为 text/event-stream
时间表示统一 Unix 秒（与现有 lease_expires_at、exp 保持一致）
字段命名snake_case（与现有 serde 配置一致，不做 camelCase 转换）
请求 ID请求头 X-Request-Id，可选。格式 ^[A-Za-z0-9._-]{1,64}$，不合规则忽略并重新生成；响应头始终回写
版本策略路径版本 /v1；破坏性变更升 /v2，同版本内只做向后兼容的字段追加

分页约定

所有列表接口使用游标分页而非 offset。游标由服务端生成、 对客户端不透明，可避免数据变动时的重复与漏项，也规避深分页的性能衰减。 limit 默认 20、上限 100，超限按上限截断而不报错。 

GET /v1/agents?capability=chat&limit=20&cursor=eyJpZCI6IjAxOTI0ZjNh...

200 OK
{
  "items": [ ... ],
  "next_cursor": "eyJpZCI6IjAxOTI1MWJj..."   // 无更多数据时为 null
}

实现陷阱：request_id 无法从 IntoResponse 取得

直觉上会为 AgentHubError 实现 IntoResponse 来统一错误输出， 但 IntoResponse::into_response(self) 只能拿到错误自身， 而 RequestId 是被上游中间件写入请求 extensions 的， 并不在错误对象里。两种可行做法：

  • 定义 ApiError { error: AgentHubError, request_id: Option<RequestId> }， 由处理器在 map 错误时把 request_id 一并带上；
  • 或让处理器返回 Result<T, ApiError>，在 ApiError 上实现 IntoResponse。

推荐后者：处理器签名统一、映射逻辑集中一处，且 ApiError 可以顺带完成审计落库。

五、中间件链

现有 build_router 的 layer 顺序会导致超时响应缺少跨域头， 且认证中间件尚未接线。修正后的链路（由外到内）： 

请求
  │
  ├─ 1. request_id     最外层，保证任何响应（含 408 / 401）都带 X-Request-Id
  ├─ 2. CORS           外移到此处，使错误响应同样携带跨域头，避免浏览器误报 CORS
  ├─ 3. TraceLayer     链路追踪，记录全周期 span
  ├─ 4. TimeoutLayer   仅挂载于非流式路由（见下方说明）
  ├─ 5. auth           凭证校验 → 注入 Principal；白名单路径跳过
  └─ 6. handler        业务处理器
CORS 必须外移：原实现中 CORS 是最内层 layer， 导致 TimeoutLayer 产生的 408、认证中间件产生的 401 都不带 Access-Control-Allow-Origin。浏览器会把它们呈现为 「CORS 错误」而非真实状态码，前端将完全无法区分「超时」与「跨域被拒」。
TimeoutLayer 会截断 SSE：全局挂载的请求超时对流式响应是致命的—— 长连接的持续时间必然超过超时阈值，连接会被强行中断。 修正方式是把 TimeoutLayer 从全局 .layer() 下移到具体路由的 .route_layer()，流式路由不挂该层， 改为在 handler 内部使用「建连超时 + 空闲超时」（两次数据块之间的最大间隔）。

认证中间件接线

修正后需要在路由上显式挂载认证，并对白名单路径放行：

Router::new()
    .route("/healthz", get(healthz))
    .route("/readyz",  get(readyz))
    // 白名单路由：不挂 auth
    .route("/v1/agents", post(register_agent))
    // 受保护路由
    .merge(
        Router::new()
            .route("/v1/agents", get(list_agents))
            .route("/v1/invoke", post(invoke))
            .route_layer(middleware::from_fn_with_state(auth_state, auth))
    )
    .layer(middleware::from_fn(request_id))   // 最外层
    .layer(build_cors(&deps.cors_allow_origins))
    .layer(TraceLayer::new_for_http())

幂等性

同一租户 + 同一 endpoint 重复提交注册时， 返回既有记录并更新 capabilities（HTTP 200 而非 201）， 不新建条目。这可以避免 Agent 重启后因首次注册未收到响应而重试， 在注册中心里堆积出多个指向同一地址的僵尸条目。

选路流程

  1. 若提供 agent_id → 校验存在性、租户归属、租约有效性；不合格直接 404。
  2. 否则取本租户在线 Agent 中 capabilities 包含 model 的集合。
  3. 集合为空 → 404 no_agent_available。
  4. 按策略择一（P1 用随机或轮询；P5 可升级为最少连接 / 加权）。
  5. 取出 RegisteredAgent.descriptor.endpoint 交给 AgentClient（见第九章）。

八、数据模型变更

新增：审计记录

当前 common 缺少调用记录模型、storage 缺少审计仓储， 这是平台「调用审计」定位的主要缺口。建议在 common::types 新增： 

pub struct AuditRecord {
    pub request_id: RequestId,      // 主键，与网关请求 ID 一致
    pub tenant_id: TenantId,        // 租户隔离字段
    pub agent_id: AgentId,          // 实际服务的 Agent
    pub model: String,              // 请求的能力标识
    pub status: AuditStatus,        // Success | Error
    pub http_status: u16,
    pub stream: bool,
    pub started_at: u64,            // Unix 秒
    pub latency_ms: u64,
    pub error_code: Option<String>, // 失败时的机器可读 code
}

pub enum AuditStatus { Success, Error }

并在 storage 中按现有 AgentRepository 的模式定义 AuditRepository（append / list / get）， 提供内存与 PostgreSQL 两种实现，由 storage.backend 统一选择。

扩展：调用请求与响应

按既定决策，InvocationRequest 增加两个可选字段， InvocationResponse 增加三个字段。默认值保证旧客户端不受影响： 

pub struct InvocationRequest {
    pub model: String,
    pub payload: serde_json::Value,
    pub stream: bool,
    #[serde(default)]
    pub agent_id: Option<AgentId>,   // 新增：定向调用
    #[serde(default)]
    pub timeout_ms: Option<u64>,      // 新增：单次超时覆盖
}

pub struct InvocationResponse {
    pub payload: serde_json::Value,
    #[serde(default)]
    pub agent_id: Option<AgentId>,    // 新增
    #[serde(default)]
    pub request_id: Option<RequestId>, // 新增
    #[serde(default)]
    pub latency_ms: Option<u64>,      // 新增
}

九、内部接口修正

第七章的接口要落地，必须先解决骨架中的三个断点。以下为建议的内部签名。

AgentClient：改为接收 endpoint

pub struct AgentClient {
    http: reqwest::Client,
    connect_timeout: Duration,
    default_timeout: Duration,
}

impl AgentClient {
    pub fn new(cfg: &GatewaySettings) -> Self;

    /// 同步调用；endpoint 由上层从注册中心取出后传入。
    pub async fn invoke(
        &self,
        endpoint: &str,
        request: InvocationRequest,
    ) -> Result<InvocationResponse>;

    /// 流式调用；返回字节流供网关透传。
    pub async fn invoke_stream(
        &self,
        endpoint: &str,
        request: InvocationRequest,
    ) -> Result<impl Stream<Item = Result<Bytes>> + Send>;

    pub async fn health(&self, endpoint: &str) -> Result<AgentStatus>;
}

理由：现有签名是 invoke(&AgentId, ...) 且文档要求「查注册中心取 endpoint」， 但该 crate 只依赖 common、不依赖 registry，实现上无法拿到地址。 把 endpoint 作为参数后，选路职责留在 ProxyService， AgentClient 保持无状态、只依赖 common，也避免了 agent → registry 的反向依赖。 同时 invoke_stream 的返回值由 Result<()> 改为字节流——原签名没有任何途径把流交给调用方，P3 必须修改。

ProxyService：需要 Principal 与审计

pub struct ProxyService {
    registry: Arc<dyn AgentRegistry>,
    client: Arc<AgentClient>,
    auditor: Arc<dyn AuditRepository>,
}

impl ProxyService {
    /// principal 用于租户隔离与审计归属，缺失则无法满足平台要求。
    pub async fn forward(
        &self,
        principal: &Principal,
        request: InvocationRequest,
    ) -> Result<InvocationResponse>;

    pub async fn forward_stream(
        &self,
        principal: &Principal,
        request: InvocationRequest,
    ) -> Result<impl Stream<Item = Result<Bytes>> + Send>;
}

当前 forward(&self, request) 既无租户信息也无审计依赖， 既无法按租户选路，也无法落审计记录，需按上述签名调整。

错误映射

新增 ApiError 承担「错误 + 请求 ID」的组合，并实现 IntoResponse， 在映射的同时触发审计落库： 

pub struct ApiError {
    pub error: AgentHubError,
    pub request_id: Option<RequestId>,
}

impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        let (status, code) = map_status_and_code(&self.error);
        // 内部错误只回通用文案，原始 message 仅进日志
        let message = match &self.error {
            AgentHubError::Internal(m) => { tracing::error!(error = %m, "internal error"); "internal error" }
            other => other.public_message(),
        };
        // ...构造统一 ErrorResponse
    }
}

十、安全设计

SSRF 防护（注册端点）

Agent 注册的 endpoint 会被网关主动发起请求， 这使得注册接口成为一个典型的 SSRF 入口：恶意注册者填入 http://169.254.169.254/latest/meta-data/ 可探测云厂商元数据服务， 填入 http://127.0.0.1:6379 可探测内网端口。必须在校验层拦截：

校验项规则
协议生产环境仅允许 https；http 仅在 development 放行
地址段解析 DNS 后拒绝：环回（127.0.0.0/8、::1）、私有网段（10/8、172.16/12、192.168/16）、链路本地（169.254/16、fe80::/10）、组播与未指定地址
端口限制在允许范围内（如 443、8443、9443），非标准端口需显式配置放行
域名生产环境建议要求注册到运维维护的域名白名单
DNS Rebinding：仅校验「解析结果」不足以防住重绑定攻击—— 攻击者先让域名解析到合法 IP 通过校验，再在网关实际发起连接前把 DNS 切到 127.0.0.1。正确做法是校验时解析出的 IP 与连接时使用的 IP 保持同一份： 自行解析得到 IP 后直接以 IP 建连并携带 Host 头， 或为 reqwest 配置自定义 resolver 缓存解析结果。

租户隔离

  • Agent 注册时绑定注册者所属租户（匿名注册绑定默认租户），后续所有查询按租户过滤。
  • 跨租户访问统一返回 404，不返回 403，避免通过状态码差异枚举资源。
  • invoke 只能调用本租户的 Agent，即使显式指定了其它租户的 agent_id。

其他

项措施
密钥管理jwt_secret 改用 SecretString（secrecy 已在依赖中却未使用），杜绝日志打印
启动校验env=production 时强制校验 JWT 密钥长度与是否仍为默认值，不合格则拒绝启动
CORS 默认值默认由 * 收紧为白名单，* 仅在 development 放行
请求体上限挂载 DefaultBodyLimit 使 gateway.max_body_bytes 生效（当前该配置项无消费方）
